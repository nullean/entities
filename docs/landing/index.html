[Constraints<Order>]
public static partial class OrderConstraints
{
    public static readonly Constraint<Order> TotalNeverNegative =
        Constraints<Order>.Always(
            o => o.Total >= 0, "An order total is never negative.");

    public static readonly Constraint<Order> CancelIsRepeatable =
        Constraints<Order>.Idempotent(o => o.Cancel());

    public static readonly Constraint<Order> VersionNeverGoesBack =
        Constraints<Order>.Monotonic(
            o => o.Version, MonotonicDirection.NonDecreasing);
}

the gap

A type system can only encode so much.

decimal Total compiles at -5. A record has a shape, not rules.

  1. Can the total ever be negative?
  2. Is cancelling twice the same as once?
  3. Does the version only go up?
Order.csthe usual answer
public class Order
{
    public Order(decimal total, int version)
    {
        if (total < 0) throw new ArgumentException(nameof(total));
        Total = total; _version = version;
    }
    public decimal Total { get; }

    public int Version
    {
        get => _version;
        set => _version = value < _version
            ? throw new InvalidOperationException()
            : value;
    }
    private int _version;
    // and cancelling twice? there is nowhere to write that down
}
  • The intent. An if says what, never why.
  • A list. Nobody can ask which rules an Order has.
  • A test. A rule inside a constructor cannot be tested on its own.
  • Reuse. The API, the options and the docs cannot read it.

the tests you did not write

One line. Nine axes.

Most tests check one example. This line asks every rule you declared these nine questions, each one a kind of production bug. Hover, focus or tap a row to watch it happen.

await AutoTest.For(OrderConstraints.Instance, Orders).RunAsync();
