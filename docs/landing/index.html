nullean.entities · .net

Types hold data.Nothing constrains it beyond its type.

Write the rules once, in plain C#. Nullean.Entities turns them into validation, state machines and thousands of generated tests. CsCheck drives them, shrinks every failure to its smallest case, and the report is clear enough for an AI to fix.

OrderConstraints.csthe rules, written once
[Constraints<Order>]
public static partial class OrderConstraints
{
    public static readonly Constraint<Order> TotalNeverNegative = Constraints<Order>.Always(
        o => o.Total, t => t >= 0, "An order total is never negative.");

    public static readonly Constraint<Order> PlacedOrdersHaveLines = Constraints<Order>
        .When(o => o.Status == OrderStatus.Placed)
        .Requires(o => o.Lines.Count > 0, "A placed order has at least one line.");

    public static readonly Constraint<Order> LegalMoves = Constraints<Order>
        .Transitions(o => o.Status)
        .Allow(OrderStatus.Draft, OrderStatus.Placed)
        .Allow(OrderStatus.Placed, OrderStatus.Paid)
        .Allow(OrderStatus.Paid, OrderStatus.Shipped)
        .Allow(OrderStatus.Placed, OrderStatus.Cancelled)
        .Allow(OrderStatus.Paid, OrderStatus.Cancelled);

    public static readonly Constraint<Order> CancelIsRepeatable =
        Constraints<Order>.Idempotent(o => o.Cancel());

    public static readonly Constraint<Order> VersionNeverGoesBack =
        Constraints<Order>.Monotonic(o => o.Version, MonotonicDirection.NonDecreasing);
}

the differentiator

Nine axes almost no test suite asks about.

Most tests check whether one example works. The generated tests ask these nine, and each one catches a specific kind of real production bug. Hover, focus or tap a row to watch the bug happen.

The nine questions and the bug each catches
#AxisQuestionThe bug it catchesAnimation
1Invariant an operation that lets a bad value in
2Idempotency a retry that changes state twice
3Monotonicity an older result overwriting a newer one
4Conservation totals that drift
5Absence a cancelled order that still ships
6Temporal a promise missed by one unlucky gap
7Liveness the endless spinner
8Confluence two rebuilds publishing different results
9Vacancy a green test that checked nothing

when it breaks

A failure you can read. So can your AI.

Each failure names the rule, the operation and the starting value, states the law that was broken and what it costs in production, and arrives shrunk to the smallest case with a seed that replays it (shrinking and seeds come from CsCheck). Rich enough for an agent to read, fix the code and replay.

one declaration

      
One rule, three jobs.

      
You wrote TotalNeverNegative once. You did not write it again in a validator, a test and a monitor.

    


    
TotalNeverNegative

    
    

      

        01
        
It validates

        
The rule checks a value where it is built, so a bad value is stopped at the door instead of three calls later.

      

      

        02
        
It tests itself

        
The rule's metadata is generated into CsCheck tests and run against machine-generated data. You write no test code for it.

        
await AutoTest.For(OrderConstraints.Instance).RunAsync();

      

      

        03
        
It can watch

        
The same rule can watch a live stream of events for the same breach.

        opt-in
      

    

    
It works on immutable records and on services or classes that change in place, and it awaits async operations.

  







  

    

      
gradual adoption

      
Start as a warning. Become an error on a date you choose.

      
Nothing breaks on the day you add a rule. Findings are reported until the date you set, and from then on they are errors.

stage 1 · relations

            
Rows point at rows.

            
An Order has many Lines, and each Line carries a foreign key. Four constraints cut across rows: Unique, References, Acyclic and NoChains. A dangling Line.OrderId turns red.

stage 3 · state machine

            
Draw what may follow what.

            
Draft, Placed, Paid, then Shipped or Cancelled. The diagram is the spec: the edge that is not there, Cancelled to Shipped, is denied. Mermaid goes in, and the same Mermaid comes out.

          

          

            
OrderMachine.cs+ added at this stage


public static readonly
    StateMachine<OrderStatus, string> Lifecycle = StateMachine
        .Define<OrderStatus, string>(OrderStatus.Draft)
        .Permit("place", OrderStatus.Draft, OrderStatus.Placed)
        .Permit("pay", OrderStatus.Placed, OrderStatus.Paid)
        .Permit("ship", OrderStatus.Paid, OrderStatus.Shipped)
        .Permit("cancel", [OrderStatus.Placed, OrderStatus.Paid],
            OrderStatus.Cancelled)
        .Build();
// no edge from Cancelled to Shipped: denied

stage 5 · services

            
Lift the same rules onto a service.

            
A mutable, async Wallet keeps its state in place. A one-unit leak shrinks to the smallest failing sequence of actions, with a seed that replays it.

          

          

            
Wallet.cs+ added at this stage


public record WalletState(int Checking, int Savings);

public class Wallet
{
    public WalletState State => new(_checking, _savings);
    private int _checking = 30, _savings = 10;

    public async Task MoveAsync(int amount)
    {
        await Task.Yield();
        if (amount <= 0 || amount > _checking) return;
        _checking -= amount;
        _savings += amount;
-       _savings += amount;
+       _savings += amount - 1;
    }
}

// rules are written against a state; Map says where it lives
public static readonly ConstraintSet<Wallet> WalletRules =
    ConstraintSet
    .From(("money-is-conserved",
        Constraints<WalletState>.Conserves(s => s.Checking + s.Savings)))
    .Map<Wallet>(w => w.State);
await AutoTest.For(WalletRules, () => new Wallet())
    .MutateAsync<int>("Move", (w, n) => w.MoveAsync(n), _ => Gen.Int[1, 12])
    .Steps(1, 6)
    .RunAsync();

    your domain, as a database model
    
      
    Think of your domain as a database model. Say its constraints.
    
      
    Orders, Lines, Customers and Categories behave like tables with keys, and the rules between them are usually implicit: a key that must exist, an id that must be unique, a tree that must not loop. This library lets you encode those rules next to the types. Break one below and the violation points at the member.
