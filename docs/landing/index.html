the whole idea, in code

Three rules, named. One line tests them.

OrderConstraints.csthree rules, named
[Constraints<Order>]
public static partial class OrderConstraints
{
    public static readonly Constraint<Order> TotalNeverNegative =
        Constraints<Order>.Always(
            o => o.Total >= 0, "An order total is never negative.");

    public static readonly Constraint<Order> CancelIsRepeatable =
        Constraints<Order>.Idempotent(o => o.Cancel());

    public static readonly Constraint<Order> VersionNeverGoesBack =
        Constraints<Order>.Monotonic(
            o => o.Version, MonotonicDirection.NonDecreasing);
}
OrderTests.csthe whole test
[Test]
public Task The_good_order_passes_every_axis() =>
    AutoTest.For(OrderConstraints.Instance, Orders).RunAsync();

the gap

A type system can only encode so much.

decimal Total compiles at -5. A record has a shape, not rules.

  1. Can the total ever be negative?
  2. Is cancelling twice the same as once?
  3. Does the version only go up?
Order.csthe usual answer
public class Order
{
    public Order(decimal total, int version)
    {
        if (total < 0) throw new ArgumentException(nameof(total));
        Total = total; _version = version;
    }
    public decimal Total { get; }

    public int Version
    {
        get => _version;
        set => _version = value < _version
            ? throw new InvalidOperationException()
            : value;
    }
    private int _version;
    // and cancelling twice? there is nowhere to write that down
}
  • The intent. An if says what, never why.
  • A list. Nobody can ask which rules an Order has.
  • A test. A rule inside a constructor cannot be tested on its own.
  • Reuse. The API, the options and the docs cannot read it.

the engine underneath

Built on CsCheck.

CsCheck is an excellent property-based testing library for .NET: fast, and it finds the smallest case that still fails. Entities builds on it, and adds what a test can't know without your rules.

Entities on top

First-class propertiesthe rules you declare, named and discoverable
Nine axeseach rule's shape says which questions to ask
AutoTestfinds the operations and runs every axis

CsCheck the engine

GeneratorsGen<T>, composed
Shrinkingto the smallest failing case
Seedsreplay exactly that case
Model-basedand parallel testing

Your rules are the properties

Each rule is a named value with a shape. The shape tells the tests what to ask, so nobody writes the property by hand. [Constraints<Order>] gathers them into OrderConstraints.All: add a rule, and it is found.

  • total-never-negativeAlways01 invariant
  • cancel-is-repeatableIdempotent02 idempotency
  • version-never-goes-backMonotonic03 monotonicity
  • label-ignores-line-orderOrderIndependent08 confluence
  • confirmed-orders-have-linesWhen · Requires01 invariant, guarded

AutoTest finds the operations AddLine Confirm Ship Cancel · every public method that returns an Order

the tests you did not write

One line. Nine axes.

Most tests check one example. This line asks every rule you declared these nine questions, each one a kind of production bug. Hover, focus or tap a row to watch it happen; tap one to read its real failure.

await AutoTest.For(OrderConstraints.Instance, Orders).RunAsync();
